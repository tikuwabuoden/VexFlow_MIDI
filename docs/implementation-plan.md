# 実装方針

## 目標

本システムの初期目標は、MIDI デバイスから入力された音をブラウザで受け取り、VexFlow による楽譜描画へ反映するまでのリアルタイム性を確認することです。

正確な自動採譜の完成を最初から目指すのではなく、以下の一連の動作を安定して確認できるプロトタイプを作成します。

```text
MIDI 鍵盤を押す
  -> MIDI 信号を受信する
  -> 受信したノート情報を画面に表示する
  -> 音符を五線譜へ追加して再描画する
```

## 初期スコープ

初期実装では以下を対象とします。

- MIDI 入力利用の許可取得
- 接続済み MIDI 入力デバイスの検出と選択
- `note on` / `note off` メッセージの受信
- MIDI ノート番号から音名および VexFlow 用キーへの変換
- 直近の入力音を五線譜に表示
- MIDI ノート番号、音名、velocity、受信時刻の確認表示
- 入力受信から画面更新までの簡易的な時間計測
- MIDI が利用できない場合やデバイス未接続の場合の状態表示

## 初期スコープ外

以下はリアルタイム表示の確認後に検討します。

- 演奏タイミングからの正確な音価推定
- テンポに基づくクオンタイズ
- 拍子および小節への厳密な割り当て
- 和音としての確定処理
- 休符、連符、タイなどの記譜処理
- MIDI ファイルの読み込みや保存
- 演奏の再生機能

## 技術構成

初期実装は、以下の構成を想定します。

| 項目 | 採用候補 | 役割 |
| --- | --- | --- |
| 開発環境 | Vite + TypeScript | 軽量な Web アプリの構築と型安全な実装 |
| MIDI 入力 | Web MIDI API | MIDI デバイス接続とメッセージ受信 |
| 楽譜描画 | VexFlow | 五線譜および音符の描画 |
| 描画方式 | SVG | DOM 上で表示結果を確認しやすくする |

## 処理フロー

### 1. MIDI 接続

アプリ起動後、ユーザー操作を起点に MIDI アクセス許可を要求します。利用可能な入力デバイスを取得し、選択中のデバイスから MIDI メッセージを受け取れる状態にします。

### 2. メッセージ解析

受信した MIDI メッセージから、メッセージ種別、ノート番号、velocity、受信時刻を取得します。`note on` かつ velocity が `0` のメッセージは `note off` として扱います。

### 3. 音名変換

MIDI ノート番号を表示用の音名と VexFlow 用のキー表現に変換します。

```text
60 -> C4 -> c/4
61 -> C#4 -> c#/4
```

初期段階では、異名同音の選択や調性に応じた表記は扱わず、変換規則を固定します。

### 4. 楽譜描画

受信した `note on` を履歴へ追加し、直近の一定数の音を VexFlow で描画します。初期表示では入力音を固定の音価として扱い、描画応答の確認を優先します。

### 5. 計測表示

入力イベントを受け取った時刻と描画完了後の時刻を記録し、イベント単位の簡易遅延を表示します。加えて、最新入力とイベントログを確認できる画面を用意します。

## 画面構成

初期画面には、以下の領域を設けます。

- MIDI デバイス選択と接続状態
- 五線譜表示領域
- 最新の入力情報
- 入力から描画までの時間表示
- 直近の MIDI イベントログ

見た目を作り込むより、入力と描画更新の対応関係および計測値を確認しやすい配置を優先します。

## ファイル構成案

```text
src/
  main.ts          # アプリケーションの初期化と画面更新
  midi.ts          # Web MIDI API の接続および入力イベント処理
  note.ts          # MIDI ノート番号と音名の変換
  notation.ts      # VexFlow による譜面描画
  types.ts         # 共有するデータ型
  style.css        # 画面スタイル
index.html
package.json
tsconfig.json
```

## 実装ステップ

1. Vite + TypeScript のアプリケーションを準備し、VexFlow を導入する。
2. MIDI 未接続状態を含む基本画面を表示する。
3. Web MIDI API に接続し、利用可能な入力デバイスと受信イベントを表示する。
4. MIDI ノート番号を音名および VexFlow 用キーへ変換する処理を実装する。
5. `note on` に応じて直近の入力音を五線譜へ描画する。
6. 受信時刻と描画完了時刻を用いた簡易遅延表示を追加する。
7. 実機で連続入力や再接続時の挙動を確認し、次段階の記譜処理に必要な課題を整理する。

## 検証項目

- MIDI デバイスを接続した状態で、入力デバイスが画面に表示されること
- 鍵盤を押した際に `note on` が受信され、対応する音名が表示されること
- 鍵盤を離した際に `note off` が受信されること
- 連続した入力で、譜面が入力順に更新されること
- 入力が速い場合でも、画面が操作不能にならないこと
- MIDI 非対応またはデバイス未接続時に、利用者が状態を判断できること
- 受信から描画更新までの簡易遅延値を確認できること

## 次段階の候補

リアルタイム表示が確認できた後は、入力時刻と `note off` を利用した音価推定、拍位置へのクオンタイズ、同時入力の和音表示、小節単位でのレイアウト更新を順に検討します。
